# Credit Scoring

Проект по кредитному скорингу: модель CatBoost оценивает вероятность дефолта, а API на FastAPI возвращает прогноз и решение об одобрении. Проект сделан для практики обучения модели и её использования в небольшом сервисе.

В репозитории есть ноутбуки с подготовкой данных и обучением, готовая модель и API. Решение об одобрении принимается, если вероятность дефолта ниже порога из `app/artifacts/config.json` (сейчас около 0,204).

## Исследование и результаты

Исследовал 150 000 записей с 10 признаками заёмщика. Доля дефолтов — около 6,7%, поэтому для сравнения моделей использовал ROC AUC и Gini, а порог решения выбирал по F1.

Что удалось найти при анализе данных:

- Обнаружил и удалил 609 дубликатов и одну запись с нулевым возрастом.
- У 225 записей все три счётчика просрочек одновременно равны 96 или 98. Доля дефолтов в этой группе — 60,4% против 6,7% в общей выборке. Сохранил эти значения как потенциально полезный сигнал.
- После удаления дубликатов доход отсутствует у 19,6% записей. В этой группе отличаются и доля дефолтов (5,66% против 6,95% при указанном доходе), и распределение `DebtRatio`. Для CatBoost сохранил пропуски, чтобы модель могла учитывать их самостоятельно.
- Нашёл экстремальные значения использования кредитного лимита: выше 200% — около 0,25% записей. Ограничил этот признак сверху значением 2, а для `DebtRatio` применил `log1p`, чтобы сжать правый хвост распределения.

В итоговом эксперименте разделил данные на train/validation/test в пропорции 70/15/15 с сохранением долей классов. Validation использовал для ранней остановки CatBoost и выбора порога, test — для итоговой оценки.

| Модель | ROC AUC на test | Gini на test |
| --- | --- | --- |
| Логистическая регрессия | 0,8539 | 70,79% |
| CatBoost | **0,8706** | **74,12%** |

Удалось улучшить логистическую регрессию до Gini **70,79%** (ROC AUC 0,8539). CatBoost дал ещё более высокий результат — Gini **74,12%** и ROC AUC 0,8706. Наибольшую важность в нём получили использование кредитного лимита, просрочки на 30–59 дней и просрочки от 90 дней.

Подобрал порог **0,2042** по максимуму F1 на validation (F1 = 0,4464). На test модель выявляет около **52% дефолтов** при precision около **40%**. Если отклонять заявки с прогнозом выше или равным порогу, на этой выборке одобряется **91,3% заявок**, а доля дефолтов среди одобренных составляет **3,55%**. При этом остаются 727 пропущенных дефолтов и 1 180 отказов заявителям без дефолта — выбор порога требует учитывать стоимость обоих типов ошибок.

## Запуск

Нужен Python 3.12. Из корня проекта:

```bash
python -m venv .venv
```

Активируйте окружение: `.venv\Scripts\Activate.ps1` в PowerShell или `source .venv/bin/activate` в Linux/macOS. Затем:

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Или через Docker:

```bash
docker build -t credit-scoring .
docker run --rm -p 8000:8000 credit-scoring
```

После запуска доступны [Swagger UI](http://localhost:8000/docs) для отправки запросов и [проверка состояния](http://localhost:8000/health).

## Пример запроса

В Swagger UI откройте `POST /predict` и отправьте:

```json
{
  "RevolvingUtilizationOfUnsecuredLines": 0.3,
  "age": 35,
  "NumberOfTime30-59DaysPastDueNotWorse": 0,
  "DebtRatio": 0.4,
  "MonthlyIncome": 5000,
  "NumberOfOpenCreditLinesAndLoans": 5,
  "NumberOfTimes90DaysLate": 0,
  "NumberRealEstateLoansOrLines": 1,
  "NumberOfTime60-89DaysPastDueNotWorse": 0,
  "NumberOfDependents": 1
}
```

В ответе будут `default_probability` — вероятность дефолта и `is_approved` — решение об одобрении. Для `MonthlyIncome` и `NumberOfDependents` можно передать `null` или пропустить эти поля.

## Что внутри

- `app/` — API, обработка входных данных и вызов модели.
- `app/artifacts/` — обученная модель и конфигурация признаков и порога.
- `notebooks/` — `01_initial_modeling_v0.1.ipynb` (первая итерация моделирования) и `02_modeling_and_validation_v1.0.ipynb` (исследование данных, обработка и оценка модели). Для запуска ноутбуков нужны дополнительные зависимости и файл `data/cs-training.csv`, которого нет в репозитории.
